依据 GitHub Wiki《迭代3计划-挑战需求A》《需求池-v3》《组内分工表》（2026-11-03 查阅）。

## 本地实现

- US-31 / 14025：后台首页改为多商品列表，支持状态、二级类别筛选、分页和逐商品意向人查询。
- US-32 / 14026：两级类别树，新增一级/二级类别、重命名、排序和确认删除。删除约束、同级重名由真实后端校验，失败保留表单。
- US-33 / 14027：库存总量维护，整数 1～99999；售罄补货后刷新状态，成交终态禁用补货。发布时填写库存。
- US-38 / 14032：注册客户分页，用户名、电话、默认交易地点、注册时间；逐客户购买历史分页，保留失败记录。
- US-35 / 14029：发布页多图上传，JPG/PNG、单张不超过 5MB，后端上限 9 张；首图为封面，可前移和移除。上传期间禁止发布，发布失败保留输入。
- 废止前端单件在售检查；发布数据使用后端 `images` / `stock` / `categoryId` 契约。继续复用卖家会话路由守卫。

入口：`/seller/admin` 或 `/seller/products`、`/seller/categories`、`/seller/customers`、`/seller/publish`。

## 验证

生产构建：在 frontend 目录执行 `npm run build`。

隔离 UI 冒烟：启动 Vite 后执行 `node tests/seller-iteration3.cjs`（需安装 Playwright 和 Chromium）。可用 `SELLER_TEST_URL` 指定服务，`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定现有 Chromium。

测试使用模拟响应，不写真实业务库；覆盖库存补货、类别新增删除、客户失败订单、多图上传与封面排序、发布请求和移动端渲染。真实数据库联调仍需运行后端后手工或端到端验收。

本次没有修改后端、买家端，也没有提交或推送 GitHub / 修改 Wiki。
