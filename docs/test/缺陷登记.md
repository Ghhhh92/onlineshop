## 缺陷列表

### BUG-01 `SellerController.me()` 未实现，登录后拿不到卖家信息
- **严重级**：中
- **所属模块**：后端卖家接口（`controller/SellerController.java`）
- **指派**：李帆
- **现象**：`GET /api/seller/me` 校验 session 后 `return Result.success(null)`，data 恒为 null。
- **修复**：主干已实现 `me()`，返回 `Result<SellerInfo>`（id + username，不含 password）；未登录由 `@RequireLogin` 拦截返回 401「请先登录」。
- **状态**：✅ 已修复（回归：`SellerAuthTest`、`LoginHttpFlowTest`）

### BUG-02 `POST /api/product/publish` 无登录校验
- **严重级**：高
- **所属模块**：后端商品接口（`controller/ProductController.java`）
- **指派**：李帆
- **现象**：发布商品接口未校验登录态，未登录也能发布商品。
- **影响**：违反 UC-07「发布商品（卖家后台）需卖家登录」。
- **修复**：主干为 `publish` 增加 `@RequireLogin`，配合 `LoginInterceptor`（注册于 `WebMvcConfig`）拦截未登录请求，返回 401「请先登录」。
- **状态**：✅ 已修复（回归：`ProductApiTest.publishWithoutLoginRejected`、`publishRejectedWithInvalidatedSession`）

### RISK-01 登录密码明文比对
- **严重级**：风险（非本迭代缺陷）
- **所属模块**：后端卖家服务（`service/SellerService.java`）
- **说明**：迭代 2 早期用明文比对。主干已引入 `spring-security-crypto` 的 BCrypt + `SellerAccountInitializer`，启动时把明文密码自动转成 BCrypt 加密存储，登录用 `PasswordEncoder.matches` 校验。
- **状态**：✅ 已解决（回归：`SellerAccountInitializerTest`）

### NOTE-01 `getOnSaleProduct()` 使用 `selectOne`
- **严重级**：低（备注）
- **所属模块**：后端商品服务（`service/ProductService.java`）
- **说明**：`selectOne` 在出现多行在售时（单件约束被绕过或历史遗留数据）会抛异常。主干发布侧已通过单件约束保证唯一，暂不影响；建议后续加防御。
- **状态**：🔍 观察中（未阻断）
